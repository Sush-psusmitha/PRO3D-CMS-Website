1. EXECUTIVE SUMMARY & OBJECTIVES
--------------------------------------------------------------------------------
The objective is to transform the new redesigned "pro3d-web" codebase into a 
full-featured Headless Content Management System (CMS) powered by Payload CMS 3 
and MongoDB, while preserving 100% of the live website's ("pro3d-OG") URL structure, 
SEO equity, backlink authority, and content taxonomy.

Key Objectives:
1. Preserve 100% of the Original URLs: Maintain exact URL paths with .html 
   extensions (e.g., /3d-modeling.html, /3d-modeling/product.html, /blog/*.html) 
   to eliminate 404 errors and protect organic search rankings.
2. Provide a Secure, Professional Admin Portal: Dedicated admin portal at 
   /admin with authentication, role-based access control, live visual preview, 
   and content versioning.
3. Modular Block-Based Page Building: Expose the 25 existing modern UI blocks 
   developed in pro3d-web as visual blocks within the CMS editor so non-technical 
   admins can build or edit any page layout dynamically.
4. Smart Phased Scope (~50 Representative Pages): Build 2-4 real pages for each 
   distinct layout template (e.g., 8 representative blog articles out of 150, 
   4 core services, 8 subservices, 4 case studies, 2 portfolio samples, and key 
   utility pages) creating a complete ~50-page foundation. The remaining pages 
   can be added effortlessly in the future via the Admin Portal without code changes.
5. Centralized Lead & Media Management: Handle quote requests, contact submissions, 
   file attachments, and optimized media assets (WebP/AVIF and 3D files).

5. APPROACH TO PRESERVING THE ORIGINAL URL STRUCTURE
--------------------------------------------------------------------------------
Preserving the exact URLs is crucial to maintain organic search ranking and 
ensure zero broken backlinks across the 254 pages.

Implementation Strategy:
1. Path Convention in CMS:
   - Each page record in the "Pages" collection will store its exact relative path 
     in a `path` field:
     * Root services: `3d-modeling.html`
     * Subservices: `3d-modeling/product.html`
     * Company pages: `about.html`, `contact.html`
     * Homepage: empty string `""`
   - Blog posts will follow `blog/{slug}.html`
   - Case studies will follow `case-studies/{slug}.html`
2. Next.js Catch-All Matching:
   - Next.js dynamic route `src/app/(frontend)/[...path]/page.tsx` receives 
     `params.path` as an array (e.g., `['3d-modeling', 'product.html']`).
   - The route joins the array with `/` (`path.join('/')`) to query MongoDB directly:
     `payload.find({ collection: 'pages', where: { path: { equals: queryPath } } })`
3. Trailing Slash & Normalization:
   - Ensure trailing slashes are consistently handled (matching OG behavior where 
     file URLs do not have trailing slashes, but directories redirect to /).
4. Permanent Redirects (301) Integration:
   - The Payload redirects plugin intercepts incoming requests; if a path matches 
     an old redirect rule (e.g. `/3d-floor-plan-conversion.html`), it issues an 
     instant 301 redirect to `/floor-plan-design.html`.

7. PHASED EXECUTION ROADMAP
--------------------------------------------------------------------------------

PHASE 1: CMS SCHEMAS & BLOCK MODELING (Preparation)
- Step 1.1: Map pro3d-web's 25 frontend blocks (in src/site/blocks) to Payload CMS 
  block configuration schemas (in src/blocks/).
- Step 1.2: Upgrade the `Pages` collection in src/collections/Pages/ to include:
  * `path` field (string, unique, indexed, with .html validation).
  * `layout` field supporting all 25 custom Pro3D blocks.
  * Enhanced SEO tab (title, description, keywords, canonical, schema).
- Step 1.3: Update `Posts` collection to reflect the structured blog layout 
  (challenges, tools, solutions, author box, sidebar widgets).
- Step 1.4: Create dedicated `CaseStudies` and `Services` collections.
- Step 1.5: Configure Header and Footer Globals to match pro3d-web's mega menu.

PHASE 2: MONGODB CONNECTION & SEED INTEGRATION
- Step 2.1: Connect real MongoDB Atlas cluster via DATABASE_URL in .env.
- Step 2.2: Run Payload migrations and initialize the database.
- Step 2.3: Create the initial Admin Superuser account for secure login.
- Step 2.4: Build a database seeder script to populate MongoDB with the 7 existing 
  pages currently in src/content/pages/ (home, about, solutions, 3d-modeling, 
  3d-modeling-product, industries-fashion, blogModelingChallenges).
- Step 2.5: Verify that the Admin Portal (/admin) displays all documents with 
  full editing capabilities.

PHASE 3: FRONTEND TO CMS WIRING & LIVE PREVIEW
- Step 3.1: Refactor `src/app/(frontend)/[...path]/page.tsx` and `page.tsx` (home) 
  to query Payload Local API (`getPayload({ config })`) instead of static arrays.
- Step 3.2: Wire Header and Footer components to fetch from Payload Globals.
- Step 3.3: Configure Next.js Draft Mode and Payload Live Preview for real-time 
  visual editing in the admin panel.
- Step 3.4: Configure Incremental Static Regeneration (ISR) and on-demand 
  revalidation hooks so pages update instantly when saved in the CMS.

PHASE 4: CONTENT INGESTION FOR THE ~50 CORE PAGES
- Step 4.1: Migrate the Core 10 Company & Utility pages (About, Contact, Pricing, 
  FAQs, Quality Assurance, Data Security, etc.) from pro3d-OG.
- Step 4.2: Build the 4 Primary Service pages and 8 Subservice pages with rich 
  service cards, subservice lists, and USPs.
- Step 4.3: Ingest the 8 representative Blog Articles into the `Posts` collection.
- Step 4.4: Ingest the 4 Case Studies and 2 Portfolio sample pages.
- Step 4.5: Migrate and optimize referenced images/media into the Payload Media library.

PHASE 5: FORMS, REDIRECTS & SEO EQUITY
- Step 5.1: Configure Payload Form Builder for Contact and Quote forms with 
  email notification triggers (SMTP/Resend).
- Step 5.2: Ingest the 50+ 301 redirects and 410 Gone rules from pro3d-OG/.htaccess 
  into Payload Redirects collection.
- Step 5.3: Generate dynamic XML Sitemaps (/sitemap.xml, /images_sitemap.xml) and 
  robots.txt.
- Step 5.4: Verify structured data schemas (Schema.org JSON-LD) across all page types.

PHASE 6: VALIDATION, BENCHMARKING & HANDOFF
- Step 6.1: Run automated crawling across the ~50 CMS pages to verify HTTP 200, 
  visual integrity, and responsive layout performance.
- Step 6.2: Validate metadata, canonical URLs, and OpenGraph social preview tags.
- Step 6.3: Audit Core Web Vitals (LCP, FID, CLS) and optimize bundle size.
- Step 6.4: Prepare Admin User Documentation so the user can easily add the remaining 
  pages in the future via the Admin Portal without writing code.
